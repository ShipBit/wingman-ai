# Test Results v3.0.1 — Qwen3.5-2B with HuggingFace-Recommended Params (2026-04-04)

## Test Matrix
- 9 prompts x 3 presets x 3 iterations = 81 total generations
- Model: Qwen3.5-2B (local, via Wingman AI Core 3.0.1)
- Presets: Precise (0.6/0.95/20/pp=0.0), Balanced (1.0/0.95/20/pp=1.5), Creative (1.0/1.0/20/pp=2.0)

## What Changed from v3.0.0
- Added `top_k=20` (was: none)
- Added `presence_penalty` (was: hardcoded 0.3, now configurable per-preset)
- Removed `frequency_penalty=0.5` (not recommended by Qwen)
- Changed default temperature from 0.3 to 1.0
- All prompts rewritten with clearer constraints
- radio-chatter `{{` double-brace bug fixed

## REMAINING ISSUES

### 1. aUEC vs SCU Confusion (extract-memories) — MODEL LIMITATION
- 8/9 iterations say "12 million SCU" instead of "12 million aUEC"
- Only 1/9 (Precise iter 3) got it right
- Despite explicit prompt instruction: "Distinguish between aUEC (currency) and SCU (cargo units)"
- This is a Qwen3.5-2B model limitation, not a prompt/param issue

### 2. Word Count Compliance (greetings) — MODEL LIMITATION
- Asked for 15-30 words, model produces 35-68 words consistently
- Only 1/9 greeting-default responses hit the range (Precise #3 at 17w)
- TTS praise (8-20 words) works fine — shorter targets are easier for the model

### 3. High presence_penalty Causes Early Stopping
- radio-chatter at pp=1.5: only 1/3 produced 5 messages (rest stopped at 3)
- radio-chatter at pp=2.0: only 1/3 produced 5 messages
- radio-chatter at pp=0.0: 3/3 produced 5 messages
- The penalty discourages repeating the JSON object structure, causing premature stop

### 4. Precise (pp=0.0) Has Repetition Risk
- condense-conversation iter 3: 17 bullets with many redundant
- greeting-returning: 3/3 identical (copied the example verbatim)
- pp=0.0 is too low for diversity-dependent tasks

### 5. Cannot Compress to 40-60% (support-default) — MODEL LIMITATION
- All presets produce output at ~95-134% of input length
- Model rephrases well but doesn't actually compress
- 2B model may lack the abstraction capability for aggressive summarization

### 6. Example-Copying (greeting-returning)
- At pp=0.0, model copies the CORRECT/WRONG example verbatim, including wrong ship name
- At pp >= 1.5, reduced but still 1/3 copy rate
- Need to remove or change the example ship name to avoid this

## PRESET CHARACTERISTICS

| Preset | Strengths | Weaknesses |
|--------|-----------|------------|
| Precise (pp=0.0) | Best for structured/factual tasks, no hallucinations, reliable message counts | Repetition risk, example-copying, zero diversity on some prompts |
| Balanced (pp=1.5) | Best all-rounder, eliminates repetition, good variety | Occasional early stopping, minor hallucinations on data tasks |
| Creative (pp=2.0) | Best diversity and creativity, fastest | Early stopping on counted tasks, invents facts, too aggressive for structured tasks |

## SUGGESTED PRESET ADJUSTMENTS

Current Precise at pp=0.0 is problematic. Consider:
- Precise: pp=0.0 → **pp=0.5** (prevents repetition without early stopping)
- Balanced: pp=1.5 — keep as-is (best all-rounder)
- Creative: pp=2.0 — keep as-is (creative tasks only)
