Embedding Inspector — Drawer Layout

How should the drawer organize and display embedding data?

A

Flat List with Expandable Cards

Summary bar at top (total chunks, memory, model info). Below it, a flat list of cached entries as cards. Each card shows tool name, token stats, timestamp. Click to expand and see chunk content previews. In "View all" mode, cards are grouped by wingman with section headers.

Pros

  • Simple, scannable
  • Everything in one scroll
  • Easy to add future sources as more cards

Cons

  • Gets long with many entries
  • No clear separation between source types
B

Tabbed by Source Type

Summary bar at top. Tabs below: "Tool Responses" (current), "Tags" (future), "Memory" (future). Each tab shows its entries as cards with stats + expandable content. Future tabs show placeholder "Coming soon" state. In "View all", each tab aggregates across wingmen with wingman badges on cards.

Pros

  • Clean separation of embedding sources
  • Scales well as sources are added
  • Tabs preview the roadmap

Cons

  • Extra click to switch tabs
  • Empty tabs feel premature
C

Accordion Sections

Summary bar at top. Collapsible accordion sections: one per source type (currently just "Tool Response Cache"). Each section shows entry count in its header, expands to show cards. In "View all", an outer accordion per wingman wraps inner source sections. Future sources get new accordion sections automatically.

Pros

  • Compact — collapse what you don't need
  • Natural hierarchy: wingman → source → entries
  • No empty placeholders needed

Cons

  • Nested accordions can feel fiddly
  • More clicks to drill down
